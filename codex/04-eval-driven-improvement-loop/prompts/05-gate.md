# 5 · 게이트 — 템플릿

이번 회차 변경을 채택할지 판정한다. **변경을 만든 주체가 판정하지 않는다.**

## 프롬프트

```
[5 - 게이트 · 회차 <N>]

Gatekeeper가 단독으로 수행한다. 이 단계에서 코드·프롬프트·데이터를
수정하지 않는다.

기준선:
- 기준선 커밋: <SHA>
- 직전 통과 회차: <N-1> / 커밋 <SHA>
- 골든셋 경로: <골든셋 경로>
- 평가 명령(dev): <dev 명령>
- 평가 명령(holdout): <holdout 명령>
- 직전 통과 회차 점수: dev <값> / holdout <값>
- 최소 개선폭: <값>

이번 회차 계획: <루프 기록>의 회차 <N> 항목
대상 유형: <유형>
허용 파일: <파일 목록>
예상 퇴행 유형: <3단계에서 적은 것>

순서대로 확인한다. 앞의 것이 실패하면 뒤를 실행하지 않는다.

1. 동결 확인
   git diff <기준선 SHA> HEAD -- <골든셋 경로>
   비어 있어야 한다. 비어 있지 않으면 즉시 실패로 판정하고 멈춘다.
   D 트랙 승인 회차면 루프 기록의 승인 항목과 대조한다.

2. 범위 확인
   git diff --stat <직전 통과 SHA> HEAD
   허용 파일 밖이 변경됐으면 실패로 판정한다.

3. dev 판정
   - 대상 유형의 실패 수가 줄었나
   - 개선폭이 최소 개선폭 이상인가
   - 대상 외 유형이 나빠졌나 — 나빠졌다면 예상 퇴행 목록에 있나

4. holdout 판정   ← 여기서 처음 연다
   holdout 평가를 실행한다. 총점과 유형별 집계만 본다.
   개별 케이스를 열지 않는다.
   - 총점이 직전 통과 회차 대비 최소 개선폭만큼 떨어지지 않았나

5. holdout 개봉 기록
   루프 기록의 개봉 카운터를 +1 한다.

판정:
- 1~4를 모두 통과 → 상태를 ROUND_APPROVAL_REQUIRED로 두고 멈춘다.
  채택은 네가 결정하지 않는다
- 하나라도 실패 → 되돌리기를 제안한다:
    git reset --hard <직전 통과 SHA>
  고쳐서 통과시키자고 제안하지 마.
  되돌리기 실행도 사람 확인 뒤에 한다

보고 형식:
| 확인 | 결과 | 근거 |
5개 항목 각각에 통과/실패와 수치를 적는다.

사람 승인에 올릴 것 (통과 시):
- 무엇을 고쳤나
- 점수가 어떻게 움직였나 (dev/holdout, 유형별)
- 이 변경이 다음 회차를 방해하지 않는 이유
- 트레이드오프가 있으면 무엇인가
- Acceptance에 얼마나 가까워졌나 (<루프 기록>의 종료 조건 대비)

승인 결과를 <루프 기록>에 남긴다:
- 승인 → 채택. 커밋하고 다음 회차로
- 반려 → 되돌린다. 반려 사유를 회차 기록에 적는다.
  반려된 접근은 다음 회차에서 그대로 다시 시도하지 않는다
```

## 채울 것

앞 단계와 동일하다. `예상 퇴행 유형`은 3단계 계획표에서 그대로 가져온다.

## 주의

### 순서가 규칙이다

1번(동결)이 실패했는데 3·4번을 돌리면, **오염된 기준으로 잰 점수**가 기록에 남는다. 나중에 그 회차의 점수를 신뢰할 수 있는지 판단할 수 없게 된다. 앞이 실패하면 뒤를 실행하지 않는다.

같은 이유로 4번(holdout)이 마지막이다. holdout은 여는 것 자체가 비용이다.

### 되돌리기가 판정이다

**게이트 실패는 되돌리기다. 고쳐서 통과시키지 않는다.**

통과할 때까지 고치면 게이트가 목표가 되고, 게이트를 목표로 최적화하면 게이트는 dev의 연장이 된다. 그 시점부터 holdout은 과적합을 막지 못한다.

되돌린 회차도 루프 기록에 남긴다. "이 트랙으로 이 유형은 안 고쳐졌다"가 다음 회차의 입력이다.

### 대상 외 유형

3번의 마지막 항목이 자주 빠진다. 총점이 올라도 **다른 유형이 나빠졌다면** 판정이 갈린다.

| 상황 | 판정 |
|---|---|
| 예상 퇴행 목록에 있다 | 트레이드오프. 사람 승인으로 올린다 |
| **목록에 없다** | 변경이 계획 범위를 넘었다. 되돌린다 |

목록에 없는 퇴행은 무엇이 왜 나빠졌는지 아무도 모른다는 뜻이다. 그 상태로 채택하면 다음 회차가 틀린 전제 위에서 진행된다.

### holdout을 여는 규칙

- **5단계에서만** 연다
- 총점과 유형별 집계만 본다. **개별 케이스를 열지 않는다**
- 열 때마다 카운터를 올린다

세 번째가 6단계 감사의 입력이다. 개봉 횟수가 회차 수에 근접하면 holdout이 사실상 dev가 된 것이다.
