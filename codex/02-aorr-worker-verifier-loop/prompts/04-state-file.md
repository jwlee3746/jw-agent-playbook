# 4 · 상태 파일 완성 — 템플릿

세션이 리셋돼도 복구할 수 있는 기준점을 만든다. 설계 단계의 마지막이며, 아직 코드를 건드리지 않는다.

## 프롬프트

```
[4 - 상태 파일 작성]

앞 단계에서 만든 상태 파일과 <설계 문서>를 읽고,
Project Settings를 보존하면서 복구용 상태 파일을 완성해.

구성:
- Project Settings (기존 값 보존)
- Goal: 한 줄
- Scope / Out of Scope
- Execution: 실행 모드, 모델, 마지막 정상 commit·URL, Rollback 기준, Last test
- Current State: 상태, 완료 루프, 다음 루프, Retry, fingerprint, blocker
- Acceptance
- Guardrails
- Retry / HITL
- Recent Loops (표)

길이 규칙:
- 항목당 한 줄
- 원시 로그, 전체 명령 출력, diff, 코드 블록 저장 금지
- 같은 섹션을 반복 추가하지 말고 현재 상태를 갱신
- Project Settings를 중복 생성하거나 임의로 바꾸지 않기
- Recent Loops는 최근 3개만
- 전체 <N>줄 이내
- 상세 실행 기록은 <로그 파일>에 저장

Guardrails:
- <금지 사항 목록>

아직 코드 수정, 테스트, push, 배포는 하지 마.
```

## 채울 것

| 자리 | 무엇을 넣나 |
|---|---|
| `<설계 문서>` | 2~3단계 산출물 |
| `<N>` | 줄 수 상한. 60줄 안쪽을 권한다 |
| `<로그 파일>` | 상세 기록을 보낼 파일명 |
| `<금지 사항 목록>` | 프로젝트별 금지. 아래 기본 항목에 덧붙인다 |

기본 Guardrails로 넣을 것:

- 확인되지 않은 사실 생성 금지, 기존 콘텐츠 임의 삭제 금지, 대규모 재작성 금지
- 테스트 삭제·완화 금지, 기능 제거로 우회 금지
- 승인 없는 외부 의존성·서비스 추가 금지
- 비밀정보를 출력·로그·코드·문서·Git에 남기지 않음

## 주의

**길이 규칙이 이 단계의 핵심이다.** 상태 파일이 커지면 컨텍스트를 잡아먹어 원래 목적을 잃는다. 상세는 별도 로그 파일로 보내고 여기에는 현재 상태만 둔다.

`Out of Scope`가 비면 루프가 돌수록 범위가 넓어진다. 무엇을 안 하는지 명시적으로 적는다.
