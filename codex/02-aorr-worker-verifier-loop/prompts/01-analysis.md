# 1 · 업무 분석 — 템플릿

작업을 루프 단위로 쪼개고 가장 안전한 첫 루프를 고른다. 코드는 건드리지 않는다.

## 프롬프트

```
[1 - 업무 분석]

<프로젝트 설정>을 상태 파일의 Project Settings에 기록해.
상태 파일이 없으면 해당 섹션만 생성해.
인증 정보는 값을 읽거나 저장하지 말고 파일명만 기록해.

<하려는 일 한 문단>

업무를 작은 개발 루프로 나누고 다음 표로 정리해:
루프 | 입력 | Act | Observe | 통과 기준 | 위험도 | HITL | 첫 루프 적합성

가장 안전한 첫 루프를 하나 추천해.
확인되지 않은 내용은 [사람 확인 필요]로 표시하고 추정하지 마.

결과를 <분석 문서>에 저장하고 핵심만 보고해.

코드 수정, 테스트, push, 배포는 하지 마.
```

## 채울 것

| 자리 | 무엇을 넣나 |
|---|---|
| `<프로젝트 설정>` | 대상 저장소, 배포 주소, 인증 파일명, 참고 자료 등 루프 내내 안 바뀌는 값 |
| `<하려는 일 한 문단>` | 최종 결과물과 제약. 기술 스택 제한이 있으면 여기 |
| `<분석 문서>` | 결과를 저장할 파일명 |

## 주의

**루프 하나는 완료 기준이 하나여야 한다.** "UI를 만든다"는 루프가 아니다. 통과/실패를 한 번에 판정할 수 있는 크기로 쪼갠다.

`첫 루프 적합성` 칸이 이 단계의 산출물이다. 실패해도 되돌리기 쉽고 다른 루프의 전제가 되는 것을 고른다.
