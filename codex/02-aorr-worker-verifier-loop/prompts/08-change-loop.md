# 8 · 항목별 재루프 — 템플릿

Change Item을 의존성 순서대로 구현한다. 배포된 것을 고치는 작업이라 회귀 테스트가 함께 돈다.

## 프롬프트

```
[8 - 변경 요청 재루프]

상태 파일, <변경 요청 문서>, <설계 문서>, 현재 코드와
마지막 정상 배포 상태를 읽고 Change Item을 의존성 순서대로 구현해.

시작 전에 상태 파일에 기록:
- 실행 모드와 모델
- 현재 commit
- 마지막 정상 commit·URL
- Git 상태
- Rollback 기준

각 Change Item:
1. Verifier가 변경 전 문제 재현 및 테스트
2. Verifier가 오류·관련 파일·fingerprint 보고
3. Worker가 승인 범위 안에서 최소 수정
4. Verifier가 동일 테스트와 관련 회귀 테스트 실행
5. 실패 시 Worker가 원인 하나만 최소 Retry
6. Verifier가 재검증
7. 전체 검증 통과 시 PASSED

규칙:
- 문서에 없는 사실 생성 금지
- 승인 범위 밖 파일 수정 금지
- 오류당 최대 <N>회, 동일 fingerprint <N>회면 BLOCKED 또는 HITL_REQUIRED
- 테스트·완료 기준 완화 금지, 기능 제거로 우회 금지
- force push, hard reset, 기록 재작성 금지
- 상세 로그는 <로그 파일>에

모든 Change Item과 전체 회귀 테스트 통과 후:
- DEPLOY_APPROVAL_REQUIRED로 설정
- 변경 항목, 변경 파일, 대상, 예상 URL을 보여주고 중지
- 사용자 승인 전 commit, push, 재배포 금지

사용자 승인 후:
1. 비밀정보 확인
2. commit과 push
3. 재배포
4. 응답 확인
5. Verifier가 배포본 회귀 테스트
6. DEPLOYED, BLOCKED 또는 HITL_REQUIRED 기록
```

## 채울 것

| 자리 | 무엇을 넣나 |
|---|---|
| `<변경 요청 문서>` | 7단계 산출물 |
| `<설계 문서>` | 2~3단계 산출물 |
| `<N>` | 재시도 상한 |
| `<로그 파일>` | 상세 기록 위치 |

## 주의

**1번의 "변경 전 문제 재현"이 6단계와 다른 점이다.** 신규 구현이 아니라 수정이므로, 고치기 전에 그 문제가 실제로 재현되는지 먼저 확인한다. 재현되지 않으면 요청을 잘못 이해했거나 이미 고쳐진 것이다.

**"마지막 정상 commit·URL"을 시작 전에 기록한다.** 되돌릴 일이 생긴 뒤에 찾으면 늦다.

**`force push`, `hard reset`, 기록 재작성 금지**를 명시한다. 배포된 것을 고치는 중이라 히스토리가 유일한 추적 수단이다. 이걸 지우면 무엇이 언제 잘못됐는지 알 수 없게 된다.

회귀 테스트는 해당 항목과 관련된 것만이 아니라, 마지막에 **전체**를 한 번 더 돌린다. 항목별로는 통과했는데 합쳐서 깨지는 경우가 있다.
