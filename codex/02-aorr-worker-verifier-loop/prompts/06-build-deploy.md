# 6 · 전체 구현과 배포 — 템플릿

남은 루프를 순서대로 돌고, 승인 게이트를 거쳐 배포한다.

## 프롬프트

```
[6 - 전체 구현과 배포]

상태 파일, <분석 문서>, <설계 문서>와 기존 코드를 읽고
작은 루프를 순서대로 실행해 전체를 완성해.

먼저:
1. Verifier 실행 가능 여부와 모델 확인
2. 실제 모델명과 실행 모드를 상태 파일에 기록

필수 범위:
- <완료해야 할 기능 목록>
- <검증할 환경·조건>

각 루프:
1. Verifier가 변경 전 테스트
2. Worker가 원인 하나를 최소 수정
3. Verifier가 동일 테스트 재실행
4. 실패 시 Verifier가 오류와 fingerprint 보고
5. Worker가 최소 Retry
6. Verifier가 다시 검증
7. 전체 검증 통과 시 다음 루프로 이동

Retry:
- 오류당 최대 <N>회, 동일 fingerprint <N>회면 중지
- 한 Retry에서는 원인 하나와 최소 파일만
- 테스트 삭제·완화 금지

기타 규칙:
- 기존 콘텐츠 보존
- 확인되지 않은 정보는 [사람 확인 필요]
- 상태 파일은 <N>줄 이내, 상세 로그는 <로그 파일>
- 미완성 기능이 있으면 PASSED 처리 금지

모든 로컬 검증이 통과하면:
- 상태를 DEPLOY_APPROVAL_REQUIRED로 설정
- 대상, 변경 내용, 예상 URL을 보여주고 중지
- 사용자 승인 전에는 commit, push, 배포 금지

사용자 승인 후:
1. 비밀정보 추적 여부 확인
2. commit과 push
3. 배포
4. 응답 확인
5. Verifier가 배포본 회귀 테스트
6. 통과 시 DEPLOYED

배포 제외: <상태 파일, 실행 로그, 인증 파일>
```

## 채울 것

| 자리 | 무엇을 넣나 |
|---|---|
| `<완료해야 할 기능 목록>` | 2단계의 "최종 목표"를 그대로 |
| `<검증할 환경·조건>` | 어느 환경에서 확인하는가 |
| `<상태 파일, 실행 로그, 인증 파일>` | 배포 산출물에서 빼야 할 것 |

## 주의

**승인 게이트에서 "보여주고 중지"가 핵심이다.** 승인을 요청하면서 동시에 준비 작업을 진행하면, 사용자가 답하기 전에 되돌리기 어려운 상태가 된다.

**"미완성 기능이 있으면 PASSED 처리 금지"**를 넣는다. 이게 없으면 통과한 항목만 세어 통과를 선언하는 일이 생긴다.

배포 전 비밀정보 확인은 사람 승인 후 첫 단계다. 승인받았다고 바로 push하지 않는다.
