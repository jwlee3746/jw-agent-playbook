# 6 · 전체 구현과 배포 — 예제

**가상 프로젝트**: [5단계 예제](05-first-loop.example.md)에서 이어진다. 루프 1(인덱스 생성)은 `PASSED`이고 루프 2~5가 남았다.

## 프롬프트

```
[6 - 전체 구현과 배포]

MEMORY.md, ANALYSIS.md, DESIGN.md와 기존 코드를 읽고
루프 2부터 순서대로 실행해 전체를 완성해.

먼저:
1. Verifier 실행 가능 여부와 모델 확인
2. 실제 모델명과 실행 모드를 MEMORY.md에 기록

필수 범위:
- 검색 페이지에서 질의 집합 12개가 모두 기대 문서를 반환
- 결과 항목에서 해당 문서로 이동 (앵커 포함)
- 검색 미사용 시 인덱스가 전송되지 않음
- 인덱스 크기 2MB 이내 유지
- 브라우저 콘솔 오류 0건

검증할 환경:
- 로컬 HTTP 서버
- 데스크톱·모바일 뷰포트
- 배포본 (승인 후)

각 루프:
1. Verifier가 변경 전 테스트
2. Worker가 원인 하나를 최소 수정
3. Verifier가 동일 테스트 재실행
4. 실패 시 Verifier가 오류와 fingerprint 보고
5. Worker가 최소 Retry
6. Verifier가 다시 검증
7. 전체 검증 통과 시 다음 루프로 이동

Retry:
- 오류당 최대 4회, 동일 fingerprint 4회면 중지
- 한 Retry에서는 원인 하나와 최소 파일만
- 테스트 삭제·완화 금지

기타 규칙:
- 기존 문서 콘텐츠 보존
- 확인되지 않은 정보는 [사람 확인 필요]
- MEMORY.md는 60줄 이내, 상세 로그는 LOOP_LOG.md
- 질의 12개 중 일부만 통과하면 PASSED 처리 금지

모든 로컬 검증이 통과하면:
- 상태를 DEPLOY_APPROVAL_REQUIRED로 설정
- 대상 저장소, 변경 파일, 예상 URL을 보여주고 중지
- 사용자 승인 전에는 commit, push, 배포 금지

사용자 승인 후:
1. deploy_token.txt와 토큰 패턴이 추적 대상·빌드 산출물에 없는지 확인
2. commit과 push
3. 배포
4. HTTP 200 확인
5. Verifier가 배포본 회귀 테스트
6. 통과 시 DEPLOYED

배포 제외: MEMORY.md, LOOP_LOG.md, ANALYSIS.md, DESIGN.md, deploy_token.txt
```

## 기대하는 승인 요청

로컬 검증이 끝나면 이런 형태로 멈춰야 한다.

```
상태: DEPLOY_APPROVAL_REQUIRED

대상 저장소: docs-site (main)
예상 URL: <배포 주소>

변경 파일 (5개)
  scripts/build-index.mjs      신규
  src/search.js                신규
  src/pages/search.html        신규
  src/layouts/base.html        수정 (검색 링크 추가)
  package.json                 수정 (build 스크립트)

로컬 검증
  인덱스        200/200 문서, 1.4MB (상한 2MB)
  질의          12/12 기대 문서 반환
  결과 이동     12/12 앵커 정상
  지연 로드     검색 미사용 시 인덱스 요청 0건
  콘솔 오류     0건
  비밀정보      추적 대상·빌드 산출물에서 0건

Retry 이력: 3회 (glob 패턴, 토큰화 공백 처리, 앵커 인코딩) — 각 원인별 1회

승인해 주시면 commit·push·배포를 진행합니다.
```

## 이 예제에서 눈여겨볼 것

- **"질의 12개 중 일부만 통과하면 PASSED 처리 금지"** — 일반 문구인 "미완성 기능이 있으면"을 이 프로젝트의 숫자로 바꿔 적었다. 구체적인 수가 있으면 부분 통과를 통과로 세는 일이 줄어든다.
- **승인 요청에 Retry 이력이 들어 있다.** 3회가 각각 다른 원인이었다는 사실이 "수렴했다"의 근거다. 같은 원인이 3회였다면 그 자체가 검토 대상이다.
- **배포 제외 목록에 설계 문서 네 개가 전부 들어 있다.** 상태 파일과 로그는 물론이고 분석·설계 문서도 배포 산출물에 들어갈 이유가 없다.
- 검증 결과가 "PASS"가 아니라 숫자로 적혀 있다. `200/200`, `12/12`, `0건`은 확인 가능하지만 "정상 동작"은 확인할 수 없다.
