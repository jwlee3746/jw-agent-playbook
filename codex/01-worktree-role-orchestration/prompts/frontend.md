# Frontend — 템플릿

UI를 구현해 화면 검증을 통과시킨다. Backend와 동시에 진행하며 서로 기다리지 않는다.

## 프롬프트

```markdown
# <task-id> · Frontend 작업 명세

## 작업장
branch `<task-id>-frontend`, 시작 branch `<기준 branch>`.
worktree를 손으로 만들지 않는다(하네스가 관리하는 경우).

## 목표
`<화면 검증 명령>` 을 PASS 시킨다.

## 구현할 것
<어느 화면·구성요소를 만드는가>
<필수 요소 식별자와 상호작용>
정확한 기대값은 `<채점 파일>` 의 <UI 계약 섹션> 을 기준으로 한다.

## 유지할 것
- <기존 화면·동작>
- <환경 제약: 프레임워크·외부 CDN 금지 등>

## 권한
- allowedFiles: <마크업·스크립트·스타일 파일>, <frontend report 경로>
- forbiddenFiles: <서버 파일>, <데이터 파일>, <검증 스크립트>, <채점 파일>
- 다른 역할의 구현 파일에 손대지 않는다

## API 계약
서버 구현은 다른 역할이 병렬로 진행 중이다.
호출 경로와 응답 형태는 `<채점 파일>` 에 정의된 것을 따르고,
서버 코드를 읽어 추론하지 않는다.

## 중단 조건
<검증 실패가 연속 N회 반복될 때 중단하고 로그를 남긴다>

## 마무리
1. `<화면 검증 명령>` 실행 → PASS 확인
2. `<frontend report 경로>` 작성 — 무엇을 왜 바꿨는지, 실행한 명령과 exit code
3. allowedFiles 만 `git add` → `git commit`
4. merge / rebase / push 금지
```

## 채울 것

| 자리 | 무엇을 넣나 |
|---|---|
| `<화면 검증 명령>` | DOM 구조·요소 존재를 확인하는 명령 |
| `<UI 계약 섹션>` | 필수 요소 식별자, 필수 상태 목록 |
| `<frontend report 경로>` | `docs/<task-id>/frontend/report.md` 형태로 고정 |

## 주의

**`API 계약` 칸이 Backend 템플릿에 없는 부분이다.** 두 역할이 동시에 진행되므로 이 시점에 서버 구현은 완성되어 있지 않다. 서버 코드를 읽고 맞추려 들면 미완성 코드에 맞추게 되고, Integration에서 어긋난다. **계약은 채점 파일에만 있다.**

필수 요소 식별자를 채점 파일에 두는 이유도 같다. 마크업의 id를 Frontend가 자유롭게 정하면 화면 검증이 무엇을 찾아야 할지 알 수 없다.
