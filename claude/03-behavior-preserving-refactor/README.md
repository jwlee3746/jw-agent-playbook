## 테스트 동결

이게 Claude Code로 옮기는 가장 큰 이유다. 프롬프트로 금지하는 것보다 확실하다.

```json
{
  "permissions": {
    "deny": [
      "Edit(./test/**)",
      "Write(./test/**)"
    ]
  }
}
```

프로젝트 `.claude/settings.json`에 두고, 경로는 실제 테스트 디렉토리로 바꾼다.

2단계(특성화 테스트 작성)와 계획표의 예외 항목에서는 이 규칙을 **잠시 뺐다가 다시 넣는다.** 뺀 사실과 이유를 계획 문서에 적는다 — 언제 열렸는지가 6단계 동등성 검증에서 대조 기준이 된다.

권한 설정을 못 쓰는 상황이면 git pre-commit 훅에서 테스트 경로 diff를 거부하는 방법이 있다. 커밋 시점에 걸리므로 권한 차단보다 늦게 잡힌다.

## plan mode

1단계(범위와 진단)와 3단계(분류와 계획)는 코드를 건드리지 않는다. plan mode로 돌리면 프롬프트의 "코드 수정하지 마"가 하네스 수준에서 지켜진다.

```bash
claude --permission-mode plan
```

4·5단계는 실제로 파일을 고쳐야 하므로 기본 모드로 돌아온다.

## Worker / Verifier

서브에이전트로 나눌 수 있지만 **같은 모델이 자기 변경을 검증하는 구성**이 된다. [codex/02의 결과](../../codex/02-aorr-worker-verifier-loop/README.md#결과)에 같은 문제가 기록되어 있다 — 교차 검증 구성을 유지하지 못하고 같은 모델로 떨어졌고, 그 구간의 판정 신뢰도는 답하지 못한 채로 남았다.

이 설계에서는 그 손실이 덜하다. 6단계 동등성 검증이 대부분 **기계가 세는 값**(git diff, 테스트 이름 목록, AST 심볼 수)이라 모델 판단에 걸린 부분이 적기 때문이다. 모델 맹점이 문제가 되는 곳은 5단계의 "예상 밖 실패인가" 판정 하나다.

가능하면 Verifier를 다른 하네스로 두되, 안 되면 그 사실을 계획 문서에 남긴다.
