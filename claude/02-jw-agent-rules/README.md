# 02 · 이 레포의 에이전트 행동 규칙

**한 줄**: [01](../01-karpathy-claude-md/)의 네 원칙 중 둘만 가져오고, 외부 자료를 다루는 레포에 필요한 규칙 하나를 더한 실사용 규칙 셋.
**출처**: 자작 — 01에서 파생
**상태**: 실험 중
**정본**: [`/CLAUDE.md`](../../CLAUDE.md) — 레포 루트에서 실제로 동작 중인 파일

사본을 이 디렉토리에 두지 않는다. 규칙 파일은 루트에 있어야 Claude Code가 읽고, 두 곳에 두면 한쪽이 반드시 낡는다. 이 문서는 **왜 그렇게 골랐는지**를 남기는 자리다.

## 용도

이 레포에서 작업할 때 에이전트가 따르는 바닥 규칙. 하네스 오케스트레이션 설계가 아니라 단일 에이전트의 행동 규칙이라는 점은 01과 같다.

## 전제

- 하네스 / 모델: Claude Code (`CLAUDE.md`를 세션 시작 시 읽음)
- 대상 레포의 성격: **코드가 아니라 문서와 설정을 모으는 저장소**. 이 전제가 아래 취사선택의 근거다
- 프로젝트별 지침을 대체하지 않고 그 위에 얹어서 씀

## 01에서 무엇을 가져오고 무엇을 버렸나

| 01의 원칙 | 결정 | 근거 |
|---|---|---|
| Think Before Coding | **채택** (규칙 1) | 거의 그대로 가져옴. 구조 결정이 많은 레포라 구현 전 질문의 가치가 큼 |
| Simplicity First | 제외 | 코드를 쓰지 않는 레포라 과설계·부풀린 추상화 위험이 낮음 |
| Surgical Changes | 제외 | 위와 같은 이유. 리팩터링할 코드가 없음 |
| Goal-Driven Execution | **채택** (규칙 3) | 거의 그대로 가져옴 |
| — | **추가** (규칙 2: 빌려오기 전에 검증한다) | 이 레포가 하는 일이 남의 작업을 모으는 것이라, 원문에 없던 축이 필요함 |

제외 사유는 위 `전제`의 "문서 저장소"에 달려 있다. 이 레포에 코드가 들어오기 시작하면 두 원칙을 다시 가져와야 한다.

규칙 2는 01에 없는 것이다. 요지는 셋이다 — 먼저 검색할 것, **검색 요약이 아니라 원본을 열 것**, 유명한 것과 여기에 맞는 것을 구분할 것.

## 결과

2026-08-02, 이 레포의 구조를 잡고 첫 두 항목을 추가하는 한 세션에서 관찰한 것이다. 표본이 하나뿐이라 `실험 중`으로 둔다.

- **잘 된 점 (규칙 1)**: 번호 체계, 외부 항목의 배치, 라이선스 처리 — 세 번 모두 구현 전에 질문이 나왔다. 특히 배치를 물어본 덕분에 나중에 디렉토리를 갈아엎는 일이 없었다.
- **잘 된 점 (규칙 2)**: 라이선스 확인 과정에서 두 번 걸렸다. (1) 검색 요약이 원작을 MIT라고 했으나 레포에 LICENSE 파일이 없었고, (2) 반대로 GitHub API는 라이선스 없음으로 보고했지만 원작 README 본문에는 MIT가 명시돼 있었다. 요약만 봤으면 양쪽 다 틀렸다.
- **실패한 점**: 규칙 2를 지키느라 라이선스 판단이 한 번 번복됐다. 결론은 맞았지만, 원본을 처음부터 끝까지 읽고 나서 결론을 냈으면 중간 번복이 없었다. "원본을 연다"에 **끝까지 읽는다**가 빠져 있다.
- **다음에 바꾼다면**: 규칙 2에 위 항목을 추가할지 검토한다. 다만 규칙이 길어지면 지켜지지 않으므로, 한 세션 더 관찰하고 결정한다.
- **관찰 안 됨 (규칙 3)**: 이번 작업에는 테스트로 검증할 대상이 없어 이 규칙이 도는 걸 보지 못했다. 코드가 있는 레포에서 따로 확인해야 한다.
