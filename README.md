# jw-agent-playbook

에이전트 하네스(harness)를 만들 때 반복적으로 꺼내 쓰는 프롬프트, 전략, 세팅을 모아두는 저장소입니다.

매번 처음부터 다시 설계하지 않기 위한 개인 레퍼런스이자, 검증된 패턴을 남들과 공유하기 위한 공간입니다.

## 구조

최상위는 하네스별로 나뉩니다. 그 아래 하네스 설계 1건이 번호가 붙은 디렉토리 하나가 됩니다.

```
00-template/         # 새 항목을 시작할 때 복사해 쓰는 틀
claude/
  01-code-review-fanout/
    README.md        # 용도 / 전제 / 결과 — 필수
    prompt.md
    strategy.md
    settings.json
codex/
  01-migration-sweeper/
    README.md
    prompt.md
    settings.toml
```

설계 1건에 필요한 프롬프트·전략·세팅은 모두 그 디렉토리 안에 둡니다. 여러 설계가 같은 조각을 공유하게 되면 그때 `shared/`를 빼되, 그 전까지는 중복을 감수합니다.

## 명명 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 하네스 디렉토리 | 소문자, 하네스 공식 이름 | `claude/`, `codex/` |
| 설계 디렉토리 | `NN-kebab-slug`, `NN`은 2자리 zero-pad | `03-test-triage-panel` |
| 내부 파일 | 역할 그대로, 확장자는 하네스 네이티브 | `prompt.md`, `settings.json` / `settings.toml` |

번호는 하네스별로 독립이며 (`claude/03`과 `codex/03`은 무관), 추가된 순서대로만 붙이고 **재사용하지 않습니다**. 항목을 지워도 그 번호는 결번으로 남깁니다. 그래야 번호가 안정적인 참조 ID가 됩니다.

`00`은 템플릿 예약 번호입니다. 최상위 [`00-template/`](00-template/)은 하네스에 속하지 않고 아래 목록에도 넣지 않습니다. 실제 항목은 `01`부터 시작합니다.

프롬프트가 여러 개면 하위 디렉토리를 파지 말고 `prompt-planner.md`, `prompt-critic.md`처럼 접미사로 구분합니다.

## 항목 추가 규칙

새 항목은 [`00-template/`](00-template/)을 목적지로 복사한 뒤 채웁니다.

```
cp -r 00-template claude/01-code-review-fanout
```

설계 디렉토리에 필수인 것은 `README.md` 하나뿐입니다. 나머지 파일은 실제로 쓰는 것만 만듭니다 — 자리만 잡아두는 빈 `prompt.md`는 두지 않습니다.

`README.md`의 섹션 구성과 각 섹션에 무엇을 적을지는 템플릿 안에 주석으로 들어 있습니다. `결과`가 핵심입니다. 잘 됐던 것만 모으면 왜 그 선택을 했는지 6개월 뒤에 알 수 없습니다.

폐기한 설계도 지우지 말고 `상태: 폐기`로 표시해 남깁니다. 왜 안 됐는지가 기록으로 남습니다.
